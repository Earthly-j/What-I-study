1. Declarative UI
------------------

Flutter uses a **declarative** style, meaning you only tell the framework **what** the UI should look like for a given state (the _final result_).

*   **How it works:** When data changes, you call `**setState()**`, and the framework automatically calculates the difference and redraws the UI.
*   **Advantage:** Code is more direct, simpler to read, and easier to maintain compared to the traditional **imperative**approach (where you manually give the system step-by-step commands to update specific UI elements).

2. Immutability
----------------

Flutter widgets are designed to be immutable (unchangeable), which enhances performance and predictability.

*   **The Widget:** The **Widget** itself is just a **lightweight configuration** (a blueprint), and all its fields must be declared as `**final**`. It never changes after creation.
*   **The State:** Any mutable (changing) data is stored separately in the associated **State** object (for a **StatefulWidget**).
*   **Benefit:** Immutability allows Flutter’s rendering engine to **efficiently compare the old widget configuration to the new one** (using the key and runtimeType), ensuring only the necessary parts of the UI are rebuilt.

3. Composition over Inheritance
--------------------------------

Flutter favors building complex UIs by combining small, single-function widgets rather than by extending large, multi-purpose classes.

*   **How it works:** You build complex structures by **nesting** simple widgets (e.g., combining `**Text**`, `**Padding**`, and `**Container**`).
*   **Advantage:** This makes components highly **reusable**, code more modular, and UI logic more flexible and easier to debug. It prevents the creation of deep class hierarchies often found in traditional development.
