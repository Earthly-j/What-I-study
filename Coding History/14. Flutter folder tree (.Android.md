📁 `**app**`: This is the most important folder. It's the actual Android app module that hosts Flutter code. Inside, we'll find:

android/src
-----------

Android-specific **source code** (like `MainActivity.kt` or `MainActivity.java`).Android/src/debug

Android/src/debug
-----------------

**Only** used when **we build the app in debug mode**.

### `AndroidManifest.xml`

Declares the app’s permissions, components, and other essential information for the Android operating system.for debugging that we wouldn’t want in a release app.

Android/src/main
----------------

This is the **primary** source set. The files here are used for all build types (debug, release, etc.).

Android/src/main/Java/
----------------------

### `**io.flutter.plugins**/GeneratedPluginRegistrant`

: This is a file **automatically generated by Flutter**. Its job is to find all the **native plugins the app uses (**like `camera`, `path_provider`, etc.) and **register them with the Android part of the app** so they can **communicate with Dart code**. Which should never edit this file manually.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*O9MpQ9SZYq8Avr1pU-JCkw.png)

Android/src/main/Kotlin/
------------------------

### `**com.example.my_first_app**/MainActivity`

This is **the most important file**. It's the **entry point for the Android** application. Think of it as the **native Android "screen" or "host" that loads and displays entire Flutter user interface.** If we need to write custom **native Android code that interacts with Flutter app**, we'll often add it to this file.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*VvkY4K6cFqCThPox18x_mg.png)

The `MainActivity.kt` code is the engineer on the other end who hears that request, walks over to the battery monitor, reads the level, and then reports it back over the intercom (`result.success(batteryLevel)`).

**we need** `**MainActivity.kt**` **because our normal Flutter code doesn't have the permission or ability to directly access native device features.** `**MainActivity**` **acts as the native bridge to perform those tasks on Flutter's behalf.**

Android/src/main/res/
---------------------

The `**res**` is short for **"resources"**. This is a standard Android directory that holds all the **non-code assets for the native Android wrapper.** Its main job in a Flutter project is to handle what the user sees **before the Flutter app has fully loaded**.

### `drawable/launch_background.xml`

This file defines the appearance of the native Android splash screen. By default, it's often just **a solid color with an icon in the middle**. We can customize this file to create a custom splash screen.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*SDYiWkV12kF74rwKvuX-sA.png)

*   `drawable-v21/launch_background.xml`: The `-v21` is a resource qualifier. It means this specific version of the file will **only** be used on Android devices running **API level 21 (Android 5.0 Lollipop) or higher**. This allows us to use newer XML features for modern devices while providing a simpler fallback for older ones

### `mipmap-`

folders are used exclusively for the app's **launcher icon**—the icon the user taps on their home screen to open the app.

*   `mdpi`: Medium density
*   `hdpi`: High density
*   `xhdpi`: Extra-high density
*   `xxhdpi`, `xxxhdpi`: Even higher densities

![captionless image](https://miro.medium.com/v2/resize:fit:1160/format:webp/1*dd41GFBZs6S1-EWOcrIq1g.png)

### `values/styles.xml`

This file defines the **visual styles and themes for the native Android part of app**. In Flutter, its primary role is to define the **Launch Theme**. This theme is applied to the splash screen, allowing to control things like the status bar color before the Flutter UI takes over.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*sXcu9N4Zl9cU_QjYbuRQ9g.png)

### `values-night/styles.xml`

The `-night` qualifier means this `styles.xml` file is used **only** when the user's phone is in **Dark Mode**. This lets the define a different splash screen theme (e.g., a dark background) to match the system theme.

Android/src/main/profiles/
--------------------------

### `**AndroidManifest.xml**`

This is for when we run the app in “profile mode” to **analyze its performance.** It also typically just **adds the** `**INTERNET**` **permission** to allow the app **to send performance data back** to the Flutter DevTools.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*101zRO8UnEZRDQ1x7W0zHA.png)

Android/src/main/
-----------------

### build.gradle. kts

The **top-level build script**. It defines configurations that apply to all modules in the project, such as the repositories where the app's **dependencies are downloaded from.**
