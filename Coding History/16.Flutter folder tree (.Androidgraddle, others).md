`android/gradle/wrapper/`
-------------------------

Instead of requiring developer to install a specific version of Gradle on their computer, the project ships with its own little “wrapper” or manager.

### `gradle-wrapper.jar`:

This is a small **Java archive file**. It's the core logic that knows how to download and **run the correct version of Gradle** for this project.

### `gradle-wrapper.properties`

A simple text file that tells the wrapper **which version of Gradle to download**. It contains a URL pointing to the Gradle distribution zip file. This ensures every developer on your team, and even your CI/CD server, uses the exact same build tool version, preventing "it works on my machine" problems.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*tN8QRK6_hZjqZVln4-pezQ.png)

### `build.gradle.kts`

This is the **top-level build script**. It defines configurations that apply to all modules within the project (in a standard Flutter app, there's just the `:app` module). Typically configure things here like:

*   The repositories where Gradle should look for plugins and dependencies (like `google()` and `mavenCentral()`).
*   The versions of the Android Gradle Plugin and Kotlin.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*btO7DUeeNxx2v06LW7CFqg.png)

### `gradle.properties`

A place to set project-wide Gradle properties. We might define version numbers for dependencies here to use them in multiple places, or configure JVM memory settings for the Gradle daemon.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*tUphNPiXnZ8fu6Idit4NUg.png)

### `gradlew`

The **Gradle Wrapper script for Linux and macOS**. When run a command like `./gradlew assembleRelease`, this script reads the `gradle-wrapper.properties` file, downloads the correct Gradle version if it's not already there, and then tells that Gradle version to run the `assembleRelease` task.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*827aG6WZypctAN2lNChdRw.png)

### `gradlew.bat`

The **Gradle Wrapper script for Windows**. It does the exact same thing as `gradlew` but for the Windows command prompt.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*Lwib7MY8LDu2bEKjgEwNFA.png)

### `local.properties`

Stores local configuration for environment, most importantly the path to Android SDK (`sdk.dir=/path/to/your/sdk`). This file is generated by Android Studio and is different for every developer.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*XtFa4tqEgShqqdvGFDenEw.png)

### `my_first_app_android.iml`

This is a project file generated by Android Studio. It contains module settings, paths, and dependencies for the IDE to understand your project structure. It's specific to the IDE.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*MJOi8Og4EjCXrFenffUjKw.png)

Why there are so many build.gradle.kts?
---------------------------------------

Two `build.gradle.kts` files is to separate **project-wide configurations** from **app-specific (or module-specific) configurations**.
