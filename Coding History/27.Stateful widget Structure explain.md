Basic Structure
---------------

this is basic structure of Stateful widget

```

class test extends StatefulWidget {
  const test({super.key});
  @override
  State<test> createState() => _testState();
}
``````
class test extends StatefulWidget {
```

*   role: the Configuration (The Blueprint)
*   Key Characteristic : **Immutable** (`final`). It holds the initial parameters (props) passed by its parent.
*   Why it Must Be Separate : Flutter needs to be able to throw this object away and create a new one every single time the parent rebuilds.

```
const test({super.key});
```

*   role : It ensures that **every** StatefulWidget **can receive a key**, which is for Flutter to efficiently **manage elements in the widget tree**, especially **when siblings of the same type change order.**
*   The `super.key` is processed and stored as an immutable property of the `MyWidget` instance. **The Widget object is now created.**

```
// createElement()
```

*   **Implicit Method:** where the `**createElement()**` method is defined
*   This method **immediately creates and returns a new** `**StatefulElement**` object. This Element is what gets inserted into the Element Tree.

```
@override
```

*   The `@override` annotation means **implementing** the `createState()` method, which is an **abstract method**required by the parent class (`StatefulWidget`).

```
State<test> 
```

The `State` is defined using a **Generic Type** (`<test>`).

This connection is vital because it allows the `State` object to access the widget's parameters safely via the `**widget**` property

```
createState() => _testState();
```

`createState()` is a **method**,

*   It **returns** a new instance of the _testState() class.
*   (`_`) means the class is **private** and only usable within the current Dart file.
*   State<test> createState() => _testState(); so it’s mean
*   State<test> _testState() return by createState
*   .aNOT State<test> createState() method

### Why Private _ used?

*   **Read-Only Access:** You cannot directly access and modify `_size` from outside the file. You are **forced to use the public** `**grow()**` **method** (or similar, like `setState`) to make changes. This is because **mutation must be controlled** to ensure the framework knows when to rebuild the UI.
*   **Immutability First:** The public face of the widget (`Bird`) remains completely immutable. This forces the programmer to _always_ remember that if they want to access the changeable part, they have to deal with the private `State` object, often using a `**GlobalKey**` (as we discussed) which is a more advanced pattern, reinforcing that state modification is a special, controlled operation.
