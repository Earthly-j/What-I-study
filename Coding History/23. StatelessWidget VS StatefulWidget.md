Stateless Widget
----------------

basically Stateless widget build() one time in it’s life cycle but depends on situation it can be rebuild more than one time !

### 1. Initial Insertion (Must Build)

**Parent’s** `**build()**`**:** A parent widget (either Stateful or Stateless) decides to include the `MyStatelessWidget` in its own layout. It calls the `MyStatelessWidget`'s **Constructor**, passing any necessary initial configuration data (properties).

### 2. Stateful `Parent Widget`

If the parent widget is stateful and stateless widget is inside of this and their variable has effected by stateful widget than it can be re-builded even if it’s stateless widget

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*aqL0Ux5VKCHsEcrP0Mll3Q.png)

### 3. Dependency Changes (InheritedWidget)

`Theme.of(context)`. `Theme.of(context)` gets its data from an `InheritedWidget` (`Theme`). If the `Theme` widget itself changes

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*9NB4INu9-NBL1QP2WROedg.png)

### 4. Hot Reload

It rebuilds the widget tree from a certain point. Even if `StatelessWidget`'s code hasn't changed

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*3YGQqIXLPs29m4DP7kL9Ag.png)

Stateful Widget
---------------

### 1. Initialization Path (Creation)

**Inserted into** the widget tree. It's about setting up the `**State**`**object and performing initial configurations** before the UI is rendered

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*iowLLnGFOJTiEOiiezCfMg.png)

### 2. External Update Path (Parent Rebuilds)

**Parent rebuilds** and provides the `StatefulWidget` with new configuration properties. The `State` **object needs to react to these external changes.**

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*uxxQzdEvsyWJRgTGsurKiw.png)

### 3. Internal Update Path (Internal State Changes)

Response to internal events, like user interaction. It's the core mechanism for making stateful widgets interactive.

![captionless image](https://miro.medium.com/v2/resize:fit:1400/format:webp/1*zfxVdI4AP1lUC1wGHa0OKw.png)

Wrap Up
-------

A `StatelessWidget` is entirely dependent on its environment for updates, whereas a `StatefulWidget` has the inherent capability to manage and trigger its own updates.
