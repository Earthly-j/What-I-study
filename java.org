Let's break down why the wording in those sentences is tricky.

### The Rule of Thumb:

- **Primitives** (like `int 100`) **STORE** values[ directly.]
- **References** (like `String "abc"`) **REFERENCE** values[ indirectly] (via an[ address]).

---

> _"The variables a and b have **reference** to the same value 100."_

If `a` and `b` are `int` variables (primitives), this sentence is **WRONG**. Primitives do not use [references]. They **store** the value directly.

Here is what actually happens with primitives:

text

int a = 100;

int b = 100;

  

Variable a Variable b

+---------+ +---------+

 | 100 | | 100 | <-- They STORE the [value] directly

+---------+ +---------+ They DO NOT reference each other.

**Corrected Sentence 1:** "The variables a and b **store** the same value 100."

  

Variable c Variable d

+---------+ +---------+

 | Addr 0 | | Addr 0 | <-- They STORE the [address] (reference)

+---------+ +---------+

 | |

V V

+-----------------+

 | "abc" | <-- The actual value is out here

+-----------------+

**Corrected Sentence 2:** "The variables c and d have **reference** to the same value "abc"."

---

### Summary:

The difference between those two statements is the mix-up between **Store** and **Reference**.

- Variables holding `100` (a primitive) [**store**] the 100. They don't reference it.
- Variables holding `"abc"` (a reference type) [**reference**] the "abc". They don't store the text itself inside the variable box.

A Class is just a blueprint. It does NOT [remember] anything. 
An Object is the actual thing built from the blueprint. IT [remembers]!
Scanner sc = new Scanner(System.in);


You ask the JVM to build: new Scanner(System.in)
JVM goes to the JRE Library: Finds the Scanner.class blueprint.
JVM "Objectifies" it: Creates a real Scanner object in memory with its own brain and memory space.
Your object borrows: Your Main object asks the Scanner object to do the reading. The Scanner object remembers the input and hands the result back to your object.



There is one tiny trick the JVM does. 

Notice how you never typed new System.out()? You just typed System.out.println(). 

That is because the JVM pre-objectifies System.out for you before your program even starts! When the JVM boots up, it automatically builds the System.out object and leaves it sitting in memory, waiting for you to use it.
